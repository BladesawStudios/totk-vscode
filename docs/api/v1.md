# TKVSC Extension API — v1

**Status:** Current  
**Shipped in:** TKVSC 0.0.3-beta.1+ (Phase 1)  
**Extension ID:** `TKVSC-Team.totk-vscode`

Core TKVSC returns a `TkvscApi` object from `activate()`. Addon extensions obtain it via:

```typescript
const api = await vscode.extensions
  .getExtension('TKVSC-Team.totk-vscode')
  ?.activate() as TkvscApi;
```

Source of truth: [`src/api/types.ts`](../../src/api/types.ts)

## Methods

### `resolveProjectRoot(item)`

```typescript
resolveProjectRoot(item: unknown): string | undefined
```

Extracts a **project folder path** from a tree context-menu item passed as the first argument to your command handler.

| `contextValue` | Resolved path |
|----------------|---------------|
| `archiveRoot` | `resourceUri.fsPath` |
| `archiveProjectDir` / `archiveProjectDirActive` | `resourceUri.fsPath` |
| `tkmmOptionsRoot` | Parent of `options/` |
| `tkmmOptionGroup` | Project root (two levels up from group) |
| `tkmmOption` / `tkmmOptionActive` | Project root (three levels up from option) |
| Other | `undefined` |

The item is duck-typed (`contextValue` + `resourceUri.fsPath`); you do not need to import TKVSC internal classes.

**Example — Package as TKCL:**

```typescript
vscode.commands.registerCommand('my-addon.packageAsTkcl', async (item) => {
  const projectRoot = api.resolveProjectRoot(item);
  if (!projectRoot) {
    void vscode.window.showErrorMessage('Could not resolve project root.');
    return;
  }
  // spawn CLI with projectRoot ...
});
```

---

### `readRawBytes(uri)`

```typescript
readRawBytes(uri: vscode.Uri): Promise<Uint8Array>
```

Reads **decompressed binary** bytes for a URI.

| URI situation | Behavior |
|---------------|----------|
| Plain `file://` on disk | Direct file read |
| `sarc://` / `totk-disk://` inside nested archive | Bridge `export-temp` (decompress + extract entry) |
| On-disk path not inside archive | Direct file read |

**Throws** if Python is not configured and archive export is required.

Use for custom editors (AINB, etc.) instead of `vscode.workspace.fs.readFile`, which returns an external-tool prompt string for unknown archive binaries.

---

### `writeRawBytes(uri, data)`

```typescript
writeRawBytes(uri: vscode.Uri, data: Uint8Array): Promise<void>
```

Writes binary bytes back to disk or repacks into a SARC entry via bridge `write-raw`.

| URI situation | Behavior |
|---------------|----------|
| Path not inside archive | `fs.writeFile` |
| Inside nested archive | Bridge `write-raw` (base64 stdin) |

**Throws** if Python is not configured and archive write is required.

---

### `getBridge()`

```typescript
getBridge(): TkvscBridgeAccess
```

Low-level access to the Python bridge for advanced addons.

```typescript
interface TkvscBridgeAccess {
  bridgePath: string;
  getPython(): string;
  getBridgeEnv(): NodeJS.ProcessEnv;
  runBridgeJsonAsync: typeof runBridgeJsonAsync;
}
```

`getBridgeEnv()` sets `TOTK_EDITOR_ROMFS` and related vars from `TKVSC.*` workspace settings.

**Example:**

```typescript
const bridge = api.getBridge();
const python = bridge.getPython();
if (!python) { return; }

const result = await bridge.runBridgeJsonAsync<{ path: string }>(
  python,
  bridge.bridgePath,
  ['export-temp', diskArchive, internalPath],
  undefined,
  bridge.getBridgeEnv(),
);
```

Prefer `readRawBytes` / `writeRawBytes` when they cover your use case.

---

### `getProjectRoots()`

```typescript
getProjectRoots(): string[]
```

Returns `fsPath` strings for all roots in the **Projects** sidebar (same folders as the archive tree).

### `registerFormatHandler(registration)`

```typescript
registerFormatHandler(registration: FormatRegistration): vscode.Disposable
```

Registers file extensions with the core format registry (language mode, editable flag, Python bridge handler kind). Merges with built-in TOTK formats and any `contributes.tkvsc` entries from other extensions.

```typescript
api.registerFormatHandler({
  extensions: ['ainb'],
  handler: 'ainb',
  language: 'yaml',
  editable: false,
});
```

| Field | Required | Description |
|-------|----------|-------------|
| `extensions` | Yes | File extensions without dot (e.g. `ainb`, `json`) |
| `handler` | Yes | Bridge handler kind string passed to Python |
| `language` | No | VS Code language ID for text editor (defaults from built-in map if known) |
| `editable` | No | Whether the format opens in the editable text pipeline (default `true`) |

Calling this refreshes `tkvsc-handler-manifest.json` in core global storage. The disposable does not unregister in v1 (restart required to remove API-registered formats).

---

### `registerBridgeHandler(registration)`

```typescript
registerBridgeHandler(registration: BridgeHandlerRegistration): vscode.Disposable
```

Registers a Python module for read/write of a handler kind (used by the bridge when the kind is not built into `totk_bridge.py`).

```typescript
api.registerBridgeHandler({
  kind: 'ainb',
  modulePath: path.join(context.extensionPath, 'python', 'ainb_io.py'),
  readFunction: 'read_content',   // optional, default read_content
  writeFunction: 'write_bytes',   // optional, default write_bytes
});
```

`modulePath` must be an absolute path on disk. Relative paths are only supported in `contributes.tkvsc` manifests (resolved against the declaring extension root).

## Declarative manifest — `contributes.tkvsc`

Addon extensions can declare formats and bridge handlers in `package.json` without calling the API at activate time. Core scans **all installed extensions** on startup (active or not).

```json
{
  "contributes": {
    "tkvsc": {
      "formats": [
        {
          "extensions": ["ainb"],
          "handler": "ainb",
          "language": "yaml",
          "editable": false
        }
      ],
      "aampExtensions": ["customext"],
      "bridgeHandlers": [
        {
          "kind": "ainb",
          "modulePath": "./python/ainb_io.py",
          "readFunction": "read_content",
          "writeFunction": "write_bytes"
        }
      ]
    }
  }
}
```

| Key | Description |
|-----|-------------|
| `formats` | Extension → handler mapping (same shape as `registerFormatHandler`) |
| `aampExtensions` | Additional extensions treated as AAMP containers (merged with `TKVSC.extraAampExtensions`) |
| `bridgeHandlers` | Python modules for dynamic dispatch (`modulePath` relative to addon root) |

Core writes a merged manifest to global storage (`tkvsc-handler-manifest.json`) and exposes it to Python via `TKVSC_HANDLER_MANIFEST`. Built-in handlers (`byml`, `msbt`, `aamp`, `asb`, `baev`, `xlnk`) remain in `totk_bridge.py`; addon kinds are loaded dynamically.

See [addon-development.md](../addon-development.md) for end-to-end examples.
